- # killall功能对比验证报告

	### 软件支持的功能清单

	| 软件功能                                                     | 原有软件 | Rust重写后的软件 |
	| ------------------------------------------------------------ | -------- | ---------------- |
	| -e,--exact          对长名字要求严格匹配                     | 支持     | 支持             |
	| -I,--ignore-case    匹配进程名时忽略大小写                   | 支持     | 支持             |
	| -g,--process-group  杀死进程组而不是进程                     | 支持     | 支持             |
	| -y,--younger-than   杀死比指定<时间>年轻的进程               | 支持     | 支持             |
	| -o,--older-than     杀死比指定<时间>年老的进程               | 支持     | 支持             |
	| -i,--interactive    在杀死进程前要求确认                     | 支持     | 支持             |
	| -l,--list           列出所有的信号名                         | 支持     | 支持             |
	| -q,--quiet          不要打印抱怨信息                         | 支持     | 支持             |
	| -r,--regexp         将 "进程名" 视为扩展正则表达式           | 支持     | 支持             |
	| -s,--signal 信号    发送指定 "信号" 而不是 SIGTERM           | 支持     | 支持             |
	| -u,--user 用户      仅杀死指定 "用户" 的进程                 | 支持     | 支持             |
	| -v,--verbose        报告信号是否成功送出                     | 支持     | 支持             |
	| -V,--version        显示版本信息                             | 支持     | 支持             |
	| -w,--wait           等待进程死亡                             | 支持     | 支持             |
	| -n,--ns 进程号      匹配与指定<进程号>具有相同命名空间的进程 | 支持     | 支持             |
	| -Z,--context 正则表达式 仅杀死含有指定上下文的进程           | 支持     | 不支持           |

	注：`-Z,--context`需要主机支持`SELinux`，openeuler虽然支持`SELinux`，但没有`libselinux`。而 crate selinux-sys 依赖`libselinux`，且这个crate是unsafe的。

	### 软件自带用例对比验证

	软件自带共14个测试点如下：

	1. 测试无选项参数运行，检测是否正常kill进程
	2. 测试`-e`参数，检测能否结束指定完整名字的进程
	3. 测试`-i`参数，检测交互模式是否正确提示用户，且正确工作
	4. 测试`-l`参数，检测是否显示所有信号名，与原有软件一致
	5. 测试`-q`参数，检测是否不输出任何信息
	6. 测试`-s`参数，检测能否发送指定的信号
	7. 测试`-v`参数，检测是否显示操作结果
	8. 测试`-I`参数，检测是否能忽略大小写匹配进程
	9. 测试`-w`参数，检测是否等待进程结束
	10. 测试`-r`参数，检测是否能使用正则表达式匹配进程名
	11. 测试`-n`参数，检测是否同namespace的进程
	12. 测试`-y`参数，检测是否只kill比指定时间年轻的进程
	13. 测试`-o`参数，检测是否只kill比指定时间年老的进程
	14. 测试`-u`参数，检测是否只kill对应user的进程

	### 功能对比验证

	1. 功能点1: 无选项参数

	- 测试方法：在测试环境中运行`killall sleep`
	- 测试结果：输出提示信息，说明需要指定进程名

	2. 功能点: `-e`参数

	- 测试方法：在测试环境中运行`killall -e sleep`
	- 测试结果：结束指定名字的进程
	- ![输入图片说明](https://foruda.gitee.com/images/1724756831689001995/4872289f_8446730.png "屏幕截图")

	3. 功能点:`	-i`参数

	- 测试方法：在测试环境中首先运行`sleep 1000&`，然后运行`killall -i sleep`
	- 测试结果：提示用户确认每个杀死的进程

	4. 功能点:`	-l`参数

	- 测试方法：在测试环境中运行`killall -l`
	- 测试结果：显示所有信号名

	5. 功能点:`	-q`参数

	- 测试方法：在测试环境中首先运行`sleep 1000&`，然后运行`killall -q sleep`
	- 测试结果：不输出任何信息

	6. 功能点:`	-s`参数

	- 测试方法：在测试环境中首先运行`sleep 1000&`，然后运行`killall -v -s SIGINT sleep`
	- 测试结果：提示进程被信号`SIGINT`杀死

	7. 功能点:`	-v`参数

	- 测试方法：在测试环境中首先运行`sleep 1000&`，然后运行`killall -v sleep`
	- 测试结果：显示操作结果

	8. 功能点:`	-V`参数

	- 测试方法：在测试环境中运行`killall -V`
	- 测试结果：显示版本信息

	9. 功能点:`	-w`参数

	- 测试方法：在测试环境中首先运行`sleep 1000&`，然后运行`killall -w sleep`
	- 测试结果：等待一段时间后进程才结束

	10. 功能点:`	-r`参数

	- 测试方法：在测试环境中首先运行`sleep 1000&`，然后运行`killall -r "sl*ep"`
	- 测试结果：sleep被杀死

	11. 功能点:`	-y`参数

	- 测试方法：在测试环境中首先运行`sleep 1000&`，然后运行`killall -y 1s`，`killall -y 1y`
	- 测试结果：前者不会杀死进程，后者会杀死进程

	12. 功能点:`	-o`参数

	- 测试方法：在测试环境中首先运行`sleep 1000&`，等待一会，然后运行`killall -o 1y`，`killall -o 1s`
	- 测试结果：前者不会杀死进程，后者会杀死进程
